# 04 AI 辅助使用与个人验证记录

## 使用范围

本项目为小影校招 AI Agent 开发岗位第 3 题（企业知识问答 Agent）的考试提交。使用 AI 助手协助梳理题目验收点、设计 CLI Agent 方案，生成项目目录、Python 初版代码、合成制度文件、离线 Mock、pytest 测试、执行 Trace 示例及文档草稿；也使用 AI 助手分析运行报错、设计真实模型验证命令、整理测试结论和复盘文档。**不将 AI 生成的代码或文字表述为完全独立手工编写。**

核心实现使用两种运行模式：`MockModel` 用来离线测试控制流程，`LiveModel` 使用配置在环境变量中的 API Key 调用真实模型。离线 Mock 验证的是流程，不应作为真实模型动态决策能力的证据。

## 本人实际操作与验证

根据本次保留的终端输出，本人已在 macOS 本地进行下列操作：

2. 配置 `OPENAI_API_KEY` 环境变量，调用真实模型运行制度冲突场景，模型依次搜索、读取 D01 和 D02，并指出“30 天”与“15 天”的冲突，没有擅自选择较新版本。
3. 运行正常问答和相似问题改写，模型检索、读取 D03，回答远程办公每周最多 2 天，并引用对应原文。
4. 运行资料外问题，模型没有编造 2027 年股票期权政策，返回 `insufficient`；但观察到检索器返回不相关文档、第二次搜索词未实质变化。

## 验证与 AI 输出核查

检查维度包括：模型是否真的选择了工具动作；工具参数和观察结果是否可追踪；回答中的文档 ID、日期和引用片段是否与 `read_document` 返回值一致；冲突时是否拒绝武断定论；工具失败时是否明确说明不能核实。七次线上运行记录分别覆盖六类必需验收场景，但有限样本**不能证明所有输入、所有运行都可靠**。

已发现的不足：资料外问题误召回报销文档；部分重试查询没有有效改写；冲突答案的 `knowledge_gap` 字段仍为 `null`，未结构化描述“适用范围和优先级缺失”。这些问题不应在文档中隐瞒。
